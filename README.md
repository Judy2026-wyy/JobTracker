# 求职追踪看板（Job Tracker）

基于 Streamlit + SQLite 的求职投递/面试进度追踪应用。

## 功能

- 上传截图，用 GPT-4o Vision 识别公司、岗位、投递进度
  - 上传文件和粘贴剪贴板放在同一个方框里，不用先选择用哪种方式，两种可以混着用
  - 所有图片统一压成正方形缩略图排成图片墙，**点图片即可选中**（绿色边框），
    支持删除选中 / 一键批量清空
- 连接 163 邮箱（IMAP），自动解析邮件中的投递/面试进度更新，预览确认后导入
- 投递去重：同一次投递不会被登记两遍（详见下方「投递去重」一节）
- SQLite 本地数据库记录投递（applications）与面试（interviews）
- 时区设置（侧边栏）：选「中国」全境统一北京时间；选其他国家再问城市/地区，
  自动换算时区。设置存库、重启仍生效，全站面试时间跟着切换
- 首页提醒条：未来 48 小时内的面试，按时间升序展示（按选定时区显示本地时间）；
  时区未确认的记录单独分组，标注"时间待确认"
- 月视图日历（streamlit-calendar），展示所有面试卡片，支持切换月份查看历史
- 投递漏斗分析：最上层总投递数、最底层 offer 数，逐层看转化率
- 简单统计：各状态数量、投递→面试转化率
- 状态严格按枚举流转：已投递 → 简历筛选中 → 笔试 → 一面 → 二面 → 三面 → HR面 → 已收offer，
  任意阶段可转为 已拒绝 / 已终止

## 文件结构


## 时区设置

侧边栏「时区设置」（在「关闭应用」按钮上方）决定所有面试时间按哪里的时间展示，
选完立刻生效并存进数据库，重启后仍是这个时区。

- 选「中国」：全境统一北京时间（UTC+8），不再追问城市。
- 选其他国家：再问城市/地区（跨时区的国家按时区档位给城市，如美国分东部/中部/
  山地/太平洋），自动换算出对应时区。
- 列表里没有的地方：选「其他」直接填 IANA 时区名，填错会当场提示、不写进库。

数据库里一律存 UTC，只有展示时才换算，**改时区不会修改任何已保存的数据**；
夏令时由 zoneinfo 按日期自动处理，不硬编码 UTC±N 偏移量。

## 投递漏斗分析

投递看板顶部的漏斗图：最上层总投递数 → 最底层 offer 数，中间依次是笔试、一面、
二面、三面，每层一种颜色并标出人数与占总投递的比例，下方明细表给出每层
「较上一阶段转化率」。

口径是「至少走到过这一层」：每条投递取它**历史上到过的最深阶段**（来自
status_history），而不是当前状态——否则"走到三面才被拒"会被算成"没进过面试"。
层级相对状态枚举做了三处裁剪：「简历筛选中」并入「已投递」层；去掉「HR面」层
（走到 HR面 的计入三面层）；去掉「已拒绝」层（被拒是每层的流失，体现为下一层
人数减少，单列会把转化率算重）。

## 投递去重

同一次投递常常会从多个渠道重复进来：截图里写「德勤」，录取通知邮件署名却是
「德勤中国」，隔几天又来一封面试邀请。三道防线保证它只在数据库里占一条记录：

1. **数据层兜底（截图 / 邮件 / 手动新增都生效）**
   公司名和岗位名归一化后一致就视为同一次投递，不看投递日期。归一化会去掉
   括号内容、`有限公司`/`集团`/`Ltd`/`Inc` 这类组织形式后缀、以及**结尾**的
   地域词（`德勤中国` → `德勤`；`中国银行`的「中国」在词首，属于名字本身，不会被删）。

2. **邮件导入时询问用户（`dedup.suggest_match`）**
   同步邮件后会逐条和库里已有的投递比对：
   - 归一化后公司和岗位都对得上 → 规则层直接判定，不消耗 API 调用；
   - 像但不敢确定（如 `PwC` 与 `普华永道`、`Deloitte China` 与 `德勤`，字符串
     相似度是 0，只有大模型认得出）→ 调一次大模型判断。
   一旦判出疑似重复，**卡片上会直接问你**「这封邮件说的是同一次投递吗」：
   - 选「是同一条」：不新建记录，把已有记录的状态往前推（允许一次跨多个阶段，
     但绝不倒退，避免一封迟到的旧邮件把 HR 面打回「已投递」），邮件信息追加到
     备注，面试时间也挂到原记录名下；
   - 选「不是同一条」：正常新建一条。
   同一次同步里如果有好几封邮件说的是同一条投递（笔试通知 + 面试通知），
   也只会登记一次。
   页面上的「用大模型判断」开关可以关掉，关掉后只用归一化规则比对，不花 API 调用。

3. **已有重复数据的清理**
   「全部记录」页面的「🧹 重复投递记录检查与合并」会扫出历史遗留的重复记录
   （分「完全重复」和「疑似重复」两类），选一条保留即可合并。合并会保留双方的
   面试安排和状态流转历史，状态取进度更靠前的，投递日期取更早的，备注拼接。

## 本地部署步骤

### 1. 准备环境

需要 Python 3.10 及以上版本（`zoneinfo` 与部分类型标注语法要求）。

```bash
python3 --version   # 确认 >= 3.10
```

### 2. 创建虚拟环境并安装依赖

```bash
cd job_tracker  # 进入本项目所在目录
python3 -m venv .venv
source .venv/bin/activate     # Windows 用 .venv\Scripts\activate
pip install -r requirements.txt
```

### 3. 配置环境变量

```bash
cp .env.example .env
```

编辑 `.env`，填入：

- `LLM_API_KEY`：OpenAI API Key（用于截图识别与邮件解析，调用 GPT-4o）
- `IMAP_HOST`：163邮箱 IMAP 服务器，默认 `imap.163.com`
- `IMAP_USER`：163邮箱完整地址
- `IMAP_PASS`：163邮箱的 **IMAP 授权码**（不是登录密码，需在163邮箱设置里单独开启 IMAP/SMTP 服务并生成授权码）

> 应用代码中已通过 `load_dotenv(find_dotenv(), override=True)` 加载 `.env`，无需额外配置。

### 4. 启动应用

```bash
streamlit run app.py
```

启动后浏览器会自动打开 `http://localhost:8501`。

### 5. 首次使用

1. 打开「全部记录」手动新增几条投递记录，或直接上传截图 / 同步邮箱
2. 在「添加面试安排」中填写面试时间和时区，未确认时区的会出现在首页"时间待确认"分组
3. 「面试月历」可切换月份查看历史与未来的面试安排

## 部署到其他环境的建议

- **同一局域网内共享**：`streamlit run app.py --server.address 0.0.0.0 --server.port 8501`，
  同网络下其他设备通过 `http://你的电脑IP:8501` 访问。
- **长期在服务器/云主机上运行**：建议用 `systemd` 或 `pm2`/`supervisor` 常驻进程，
  并在前面加 nginx 反向代理 + HTTPS。
- **Streamlit Community Cloud / Docker**：如需要，可在此基础上补充 `Dockerfile` 或
  推送到 GitHub 后连接 share.streamlit.io（需要你自己的账号，此环境无法代为操作）。

## 已知限制 / 注意事项

- LLM 识别结果可能有误，截图识别与邮件解析结果均设计为"预览-确认"后再写入数据库，
  请务必人工核对公司名、岗位名、状态与时间。
- 163 邮箱 IMAP 需要账号中显式开启 IMAP/SMTP 服务，并使用授权码而非登录密码。
- 邮件中若未明确写出时区，程序默认按 `Asia/Shanghai`（北京时间）解释原始时间再换算为
  America/Chicago，且该记录会被标记为 `timezone_confirmed=False`，需要人工确认。
- 转化率统计口径：已产生至少一条面试记录的投递数 / 总投递数（不依赖 status 字段，
  因为状态一旦转为"已拒绝/已终止"会覆盖此前的阶段信息）。
- `job_tracker.db` 请放在本地磁盘目录下运行（不要放在网络盘/云同步盘的实时同步路径中），
  部分网络文件系统对 SQLite 的文件锁支持不好，可能报 `disk I/O error`。
