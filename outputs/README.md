# 求职追踪看板（Job Tracker）

基于 Streamlit + SQLite 的求职投递/面试进度追踪应用。

## 功能

- 上传截图或直接从剪贴板粘贴截图，支持一次提供多张图片，大模型会把这些图片放在
  一起综合识别（同一条记录拆在几张图里的会自动合并，多条不同记录会自动拆分），
  逐条核对、可勾选跳过后一次性保存
- 截图识别会把岗位核心信息**完整提炼进备注**（工作地点、部门、招聘类型、学历与经验
  要求、薪资、技能要求、投递渠道、截止日期、职位编号、志愿顺序等），按「字段：值」
  逐行罗列，以后回看不用再翻截图；提示词里明确**禁止编造和扭曲事实**——只写截图里
  真实出现的内容，不用常识补全、不改写数字与日期、看不清的直接不写也不猜
- 上传/粘贴的图片支持批量管理：可勾选任意几张点击「删除选中的图片」，或一键
  「清除全部图片」重新开始
- 连接 163 邮箱（IMAP），自动解析邮件中的投递/面试进度更新，预览确认后导入；
  候选记录按邮件类型（笔试 / 面试 / offer通知 / 其他）分 tab 展示，不想入库的
  邮件可以「跳过」（本次不导入、仍留在原分组）或「忽略」（本次不导入、并归到
  「其他」分组），两种操作都能一键恢复，且都不会动 163 邮箱里的原始邮件
- SQLite 本地数据库记录投递（applications）与面试（interviews）
- 首页提醒条：未来 48 小时内的面试，按时间升序展示（美国达拉斯 America/Chicago 本地时间）；
  时区未确认的记录单独分组，标注"时间待确认"
- 首页投递趋势折线图：X 轴为投递日期、Y 轴为当日投递数，默认展示近一周走势，
  可切换统计周期（最近7/30/90天或全部），悬停查看具体某天的投递数
- 投递看板「投递进度时间线」以水平进度条形式展示每条投递：一条投递一根横条，
  按 已投递→简历筛选中→...→当前状态 的实际流转拆成多段分别着色，每段开头
  标注进入该阶段的日期（如 `7/31`），一眼看出每个阶段停留了多久
- 月视图日历（streamlit-calendar），展示所有面试卡片，支持切换月份查看历史
- 简单统计：各状态数量、投递→面试转化率
- 状态严格按枚举流转：已投递 → 简历筛选中 → 笔试 → 一面 → 二面 → 三面 → HR面 → 已收offer，
  任意阶段可转为 已拒绝 / 已终止；10 个状态的颜色经过 OKLab 色差校验，确保彼此
  能明显区分，不会出现"看起来都差不多"的相近色
- 投递看板「最大间隔天数」按完整天数（整数）统计，不出现带小数的天数
- 岗位分类采用 29 个一级类目的职能分类体系（后端开发 / 前端开发 / 算法 /
  AI大模型 / 数据 / 产品 / 设计 / 运营 / 财务 / 法务合规风控 …），并把类目下的
  典型岗位关键词和一套消歧规则一起写进 LLM 提示词，让大模型分类更准更稳定
- 侧边栏底部提供「🛑 关闭应用」按钮（带二次确认），不熟悉命令行也能直接在
  网页上安全地关闭应用

## 本地部署步骤

### 1. 准备环境

需要 Python 3.10 及以上版本（`zoneinfo` 与部分类型标注语法要求）。

```bash
python3 --version   # 确认 >= 3.10
```

### 2. 创建虚拟环境并安装依赖

```bash
cd job_tracker  # 进入本项目所在目录
python3 -m venv .venv
source .venv/bin/activate     # Windows 用 .venv\Scripts\activate
pip install -r requirements.txt
```

### 3. 配置环境变量

```bash
cp .env.example .env
```

编辑 `.env`，填入：

- `LLM_API_KEY`：OpenAI API Key（用于截图识别与邮件解析，调用 GPT-4o）
- `IMAP_HOST`：163邮箱 IMAP 服务器，默认 `imap.163.com`
- `IMAP_USER`：163邮箱完整地址
- `IMAP_PASS`：163邮箱的 **IMAP 授权码**（不是登录密码，需在163邮箱设置里单独开启 IMAP/SMTP 服务并生成授权码）

> 应用代码中已通过 `load_dotenv(find_dotenv(), override=True)` 加载 `.env`，无需额外配置。

### 4. 启动应用

```bash
streamlit run app.py
```

启动后浏览器会自动打开 `http://localhost:8501`。

### 5. 首次使用

1. 打开「全部记录」手动新增几条投递记录，或在「上传截图」中选择文件上传（可一次
   选多张），也可以先复制截图到剪贴板，切到「📋 粘贴截图」标签页，点击按钮后按
   Ctrl+V（Mac 为 Cmd+V）粘贴，可重复粘贴多张；多张图片会一起交给大模型综合识别，
   同一条记录拆在几张图里的会自动合并，不同记录会自动拆分；传错了可以勾选后
   「删除选中的图片」，或直接「清除全部图片」重来；或直接同步邮箱
2. 「邮箱同步」点「开始同步」后，候选邮件会按 笔试 / 面试 / offer通知 / 其他
   四个 tab 分组列出：想入库的保持勾选，不想入库的点「⏭️ 跳过」或
   「🚫 忽略（归到其他）」，点错了再点「↩️ 恢复」即可；最后点「导入勾选的记录」
3. 在「添加面试安排」中填写面试时间和时区，未确认时区的会出现在首页"时间待确认"分组
4. 「面试月历」可切换月份查看历史与未来的面试安排
5. 首页「投递趋势」折线图可以切换统计周期，看看自己最近投递节奏怎么样

## 岗位分类体系

分类定义集中在 `config.py` 的 `JOB_TAXONOMY`（类目 -> 典型岗位关键词），
`CATEGORIES` 由它直接展开，改分类只需要动这一处。

设计原则：

1. **单一维度**——只按「职能」切分，不混入行业/技术栈/职级。
2. **互斥优先**——相邻类目给出边界说明（`DISAMBIGUATION_RULES`），减少模型摇摆。
3. **可扩展**——新岗位先进已有类目，某个方向的记录多到需要单独看时再升为一级类目。
4. **兜底保留**——「其他」永远排在最后且不给关键词，强制模型先尝试其他类目。

提示词里除了类目名，还会带上每个类目的典型岗位关键词和消歧规则（由
`build_category_prompt_block()` 拼装，截图识别与邮件解析共用同一份，不会两边写岔）。

`normalize_category()` 做了多层兜底，依次尝试：合法类目名 → 旧类目名映射 →
关键词精确匹配 → 关键词子串匹配（长词优先），全都不中才落到「其他」。
这样即使模型输出的是 `后端工程师`（关键词而非类目名）或 `Java后端开发工程师`
（带修饰的岗位名），也能正确归到「后端开发」，而不是白白丢成「其他」。

### 用大模型重新归类历史记录

「全部记录」页面的 **🔄 用当前分类体系重新归类历史记录** 折叠面板，可以把已入库的
记录交给大模型按当前分类体系重新判定（`category_classifier.py`）：

- **处理范围**可选「只处理没归好类的」（旧类目遗留值 + 被归成「其他」的）或「全部记录」。
- 一次请求**批量**处理多条（默认 40 条一批），不会逐条调用，省 token 也快。
- 结果先以 `原分类 → 建议分类` 的形式列出来预览，逐条可取消勾选，
  **确认后才写库**，跟截图识别、邮箱同步保持同一套"预览-确认"逻辑。
- 模型没给出结果的记录会保持原样不动，不会被硬塞一个「其他」覆盖掉原本可能是对的分类；
  模型若编造了不存在的记录 id 也会被丢弃。

### 历史数据迁移

`db.init_db()` 启动时会自动调用 `_migrate_legacy_categories()` 回填旧分类
（如 `测试` → `测试/质量保障`、`人力` → `人力资源`），可重复执行、不会重复改写。

但 `开发`、`算法/AI`、`市场/销售`、`人力/财务/行政` 这几个旧类目属于**一对多拆分**，
无法自动判断该归到哪个新类目（比如「开发」可能是后端/前端/客户端/嵌入式），
迁移时会**保持原值不动**——自动猜一个大概率是错的，宁可留着让你自己改，或者
重新识别一次那条记录。这些没迁移的旧值仍然会出现在筛选器选项的末尾，不会因为
「不在新类目列表里」就被静默过滤掉。

## 部署到其他环境的建议

- **同一局域网内共享**：`streamlit run app.py --server.address 0.0.0.0 --server.port 8501`，
  同网络下其他设备通过 `http://你的电脑IP:8501` 访问。
- **长期在服务器/云主机上运行**：建议用 `systemd` 或 `pm2`/`supervisor` 常驻进程，
  并在前面加 nginx 反向代理 + HTTPS。
- **Streamlit Community Cloud / Docker**：如需要，可在此基础上补充 `Dockerfile` 或
  推送到 GitHub 后连接 share.streamlit.io（需要你自己的账号，此环境无法代为操作）。

## 已知限制 / 注意事项

- LLM 识别结果可能有误，截图识别与邮件解析结果均设计为"预览-确认"后再写入数据库，
  请务必人工核对公司名、岗位名、状态与时间。
- 163 邮箱 IMAP 需要账号中显式开启 IMAP/SMTP 服务，并使用授权码而非登录密码；
  客户端必须在 `LOGIN` **之前**成功发送 `ID` 命令自报身份，否则会收到
  `SELECT Unsafe Login` 报错。这里有个不太直观的坑：Python `imaplib` 内置的
  命令状态校验表里根本不认识 `ID` 这个命令，直接调用会在写 socket 之前就抛
  `KeyError`，如果外层用宽泛的 `except Exception` 包住，会把这个报错静默吞掉、
  误以为"ID 已经发送但服务器不需要"，实际上 ID 从来没有发出去过。本项目已在
  `email_import.py` 里把 `"ID"` 注册进 `imaplib.Commands` 再发送，正常情况下
  无需手动干预。
- 若同步时报 `LOGIN Login error or password error`，说明是账号/密码认证本身
  失败（跟上面的 ID 顺序问题是两回事），请逐项检查：`IMAP_USER` 是完整邮箱
  地址；`IMAP_PASS` 是163邮箱「设置 - POP3/SMTP/IMAP - 客户端授权密码」页面
  生成的授权码而非登录密码；如果最近重新生成过授权码，需要把 `.env` 里的值
  同步更新，并确认复制时没有带上多余的空格或引号（代码已对读到的值做了
  `strip()` 防御处理，但 `.env` 文件本身的内容需要你自己确认）。
- 邮件中若未明确写出时区，程序默认按 `Asia/Shanghai`（北京时间）解释原始时间再换算为
  America/Chicago，且该记录会被标记为 `timezone_confirmed=False`，需要人工确认。
- 转化率统计口径：已产生至少一条面试记录的投递数 / 总投递数（不依赖 status 字段，
  因为状态一旦转为"已拒绝/已终止"会覆盖此前的阶段信息）。
- `job_tracker.db` 请放在本地磁盘目录下运行（不要放在网络盘/云同步盘的实时同步路径中），
  部分网络文件系统对 SQLite 的文件锁支持不好，可能报 `disk I/O error`。
- 「粘贴截图」功能基于浏览器剪贴板 API，需要在 `https://` 或 `localhost` 环境下使用；
  部分浏览器首次使用时会弹出剪贴板读取权限确认，允许即可。
- 页面右上角的「Rerun / Clear cache / Settings」等开发者菜单和对应的键盘快捷键
  （Streamlit 默认单独按 `c` 键即可触发"清除缓存"）已通过 `.streamlit/config.toml`
  的 `toolbarMode = "viewer"` 关闭，避免用 Ctrl+C 复制页面文字时误触发清除缓存
  确认框。补充说明：本应用没有使用 `st.cache_data` / `st.cache_resource`，所有
  投递/面试记录都在 `job_tracker.db` 这个 SQLite 文件里，即使触发"清除缓存"也
  不会丢失任何已保存的数据。
- 想关闭应用时，点侧边栏底部的「🛑 关闭应用」→「✅ 确认关闭」即可（会有一次
  二次确认，防止手滑点错），不需要去命令行或任务管理器里找进程。关闭后浏览器
  标签页可以直接关掉，下次要用再重新 `streamlit run app.py` 启动。
